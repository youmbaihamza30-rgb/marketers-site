# كتالوج المسوّقات

موقع كامل (واجهة + قاعدة بيانات + تخزين صور) مخصص لعرض أسعار وصور المنتجات وأسعار التوصيل
للمسوّقات، مع لوحة تحكم كاملة للإدارة. مبني بدون Firebase إطلاقاً.

## لماذا هذه التقنيات؟

| الطبقة | التقنية | السبب |
|---|---|---|
| الواجهة + السيرفر | **Next.js** (React) | مشروع واحد يجمع الواجهة و API، سريع، ويُنشر مجاناً على Vercel |
| الاستضافة | **Vercel** | نشر مجاني للمشاريع الصغيرة/المتوسطة، يتوسّع تلقائياً مع نمو عدد الزوار |
| قاعدة البيانات | **Supabase (Postgres)** | قاعدة بيانات حقيقية وقوية (وليست Firebase)، مجانية حتى 500 ميجابايت ثم بخطة رخيصة ~25$/شهر تكفي لسنوات من النمو |
| تخزين الصور | **Supabase Storage** | مبني على S3، رفع مباشر من المتصفح دون المرور بالسيرفر (مهم لرفع عشرات الصور دفعة واحدة)، يحفظ الصور بجودتها الأصلية دون أي ضغط |
| تسجيل الدخول | نظام كلمة مرور مخصص (بدون Supabase Auth) | يطابق طلبك بالضبط: كلمتا مرور فقط، بدون بريد أو اسم مستخدم |
| ترتيب المنتجات | `@dnd-kit` | مكتبة سحب وإفلات خفيفة وموثوقة |

هذا التصميم قابل لاستيعاب آلاف المنتجات وعشرات آلاف الصور دون أي تغيير في البنية،
لأن Postgres وStorage كلاهما مصمّمان أصلاً لهذا الحجم.

## هيكلة المشروع

```
app/
  login/              صفحة تسجيل الدخول
  (site)/             واجهة المسوّقات (قراءة فقط): المنتجات، الصور، التوصيل
  admin/              لوحة الإدارة الكاملة
  api/                كل واجهات البرمجة (Auth، المنتجات، الصور، التوصيل، الإعدادات)
lib/                  اتصال Supabase، الجلسات، التحقق من الصلاحيات
components/           مكوّنات الواجهة القابلة لإعادة الاستخدام
supabase/schema.sql   سكيما قاعدة البيانات الكاملة
scripts/init-admin.js سكربت لضبط كلمتي المرور الأوليتين
```

## خطوات التشغيل (مرة واحدة)

### 1) إنشاء مشروع Supabase
1. أنشئ حساباً مجانياً على supabase.com وأنشئ مشروعاً جديداً.
2. من **SQL Editor** نفّذ محتوى ملف `supabase/schema.sql` بالكامل (ينشئ كل الجداول).
3. من **Storage**، أنشئ Bucket جديداً باسم `product-images` (أو أي اسم، لكن يجب أن يطابق
   قيمة `NEXT_PUBLIC_SUPABASE_STORAGE_BUCKET` في `.env`)، واجعله **Public** حتى تُعرض الصور مباشرة للمسوّقات.
4. من **Project Settings > API** انسخ: `Project URL`، `anon public key`، `service_role key`.

### 2) إعداد متغيرات البيئة
انسخ `.env.example` إلى `.env` واملأ القيم (روابط ومفاتيح Supabase، وكلمتي مرور ابتدائيتين
لأول تشغيل، وسلسلة عشوائية طويلة لـ `SESSION_SECRET`).

### 3) تثبيت الحزم وتهيئة كلمتي المرور
```bash
npm install
node scripts/init-admin.js
```
هذا يشفّر كلمتي المرور من `.env` ويخزّنهما في قاعدة البيانات. بعدها يمكنك تغييرهما في أي وقت من لوحة الإدارة.

### 4) التشغيل محلياً للتجربة
```bash
npm run dev
```
افتح http://localhost:3000

### 5) النشر (مجاناً)
1. ارفع المشروع إلى مستودع GitHub.
2. أنشئ حساباً على vercel.com واستورد المستودع.
3. أضف نفس متغيرات `.env` في إعدادات المشروع على Vercel (Environment Variables).
4. اضغط Deploy. سيصبح الموقع متاحاً على رابط دائم خلال دقائق.

## ملاحظات مهمة
- كل الكتابة على قاعدة البيانات تمر حصراً عبر واجهات API في السيرفر باستخدام
  `service_role key`، ولا يصل المتصفح أبداً إلى قاعدة البيانات مباشرة (RLS مفعّل بدون أي صلاحيات عامة).
- رفع الصور دفعة واحدة (30/50/100 صورة) يتم مباشرة من المتصفح إلى Supabase Storage
  عبر روابط رفع موقّعة (Signed Upload URL) يولّدها السيرفر، فلا حدود على حجم أو عدد الملفات المرفوعة دفعة واحدة.
- زر "تحميل الصورة" يحمّل الملف كما هو دون أي إعادة ضغط، لأن Storage يحتفظ بالملف الأصلي كما رُفع.
- لإضافة قسم صور جديد: اذهب إلى **لوحة الإدارة > الأقسام** وأضفه، سيظهر تلقائياً في قسمي المنتجات والصور.
- المشروع مبني بـ JavaScript عادي (بدون TypeScript) وبنية ملفات بسيطة وواضحة ليسهل عليك
  أو على أي مطوّر آخر إضافة ميزات جديدة مستقبلاً (مثال: طلبات المسوّقات، إحصائيات مبيعات...) دون إعادة بناء الموقع.

## أفكار للتوسع المستقبلي (البنية تدعمها دون تعديل جذري)
- إضافة عمود `commission` لكل منتج لحساب عمولة كل مسوّقة.
- سجل نشاط (من غيّر ماذا ومتى).
- تصدير قوائم الأسعار كملف PDF أو Excel.
- إشعارات عند إضافة منتجات جديدة.
